What you get

FieldExampleNotes
isoCountry "US" ISO 3166-1 alpha-2 code; "001" for non-geographic codes
callingCode 1 ITU-T E.164 country calling code
nationalPrefix "1" Digit dialled before a national number, or null
digits [10] Every valid national number length, from possibleLengths, sorted
exampleNumber "2015550123" A valid national example from the metadata
nationalFormat "(201) 555-0123" The example number shaped by the territory's first matching format — null when the pattern is a Java-only regex
internationalFormat "201-555-0123" Same for the international format — null when unavailable

How it stays fresh

The update.yml workflow runs weekly, fetches PhoneNumberMetadata.xml from the libphonenumber project, regenerates the JSON and commits only when the data actually changed. GitHub Pages serves the result. No server to run.

Data source and accuracy

The source is the PhoneNumberMetadata.xml maintained by Google's libphonenumber project — the same metadata that backs Android, iOS and Java phone validation. All 254 territories are included; every record carries an example number, and 207 also carry a matching national/international format. Digit lengths come from possibleLengths at the national level.

Limits, stated plainly

  • 47 of 254 territories have no nationalFormat/internationalFormat — their patterns are Java regexes a JavaScript engine rejects. The raw validation fields are still complete.
  • Format patterns are not exposed; only the formatted result is. Use libphonenumber directly if you need full pattern data.
  • Formats are illustrative — the example number shaped by the first matching pattern — not a guarantee for every real number.
  • libphonenumber updates its metadata frequently, so expect a weekly commit most weeks.
